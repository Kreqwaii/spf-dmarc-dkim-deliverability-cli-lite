# spf-dmarc-dkim-deliverability-cli-lite

Zero-dependency Python 3.9+ CLI with a native RFC 1035 DNS client to audit domain **MX**, **SPF** (10-lookup RFC 7208 limit), **DMARC**, and **DKIM** deliverability hygiene — generating a 0–100 health score and exact copy-paste DNS fix records.

---

## Features

- **Zero external dependencies**: Pure Python 3.9+ standard library (`argparse`, `base64`, `csv`, `json`, `socket`, `struct`, etc.). No `dnspython`, `pip install`, or virtual environment required.
- **Native RFC 1035 DNS wire client**:
  - Builds and parses raw UDP DNS packets with Section 4.1.4 pointer compression (`0xC0xx`), loop protection, multi-chunk TXT string concatenation, CNAME chasing, and automatic TCP fallback on truncated (`TC=1`) responses.
  - Includes an injectable `MockDnsResolver` for 100% deterministic offline unit tests and CI simulations.
- **MX Hygiene Audit (`0–20 pts`)**: Verifies MX presence, priority ordering, RFC 7505 Null MX (`0 .`) detection, and hostname target sanity.
- **SPF RFC 7208 Audit (`0–30 pts`)**:
  - Recursively walks `include:` and `redirect=` chains to compute the exact DNS lookup count against the **10-lookup RFC 7208 limit** (including `a`, `mx`, `ptr`, `exists`, `include`, and `redirect`, while correctly excluding `ip4`, `ip6`, `all`, and `exp=`).
  - Detects duplicate `v=spf1` TXT records (`PermError`), insecure `+all` / bare `all` / `?all` qualifiers, circular include loops, broken includes, and deprecated `ptr` usage.
- **DMARC RFC 7489 Audit (`0–30 pts`)**: Checks `_dmarc.<domain>` for duplicate records, policy enforcement (`p=reject` / `p=quarantine` / `p=none`), `pct=` rollout percentage, alignment (`adkim`, `aspf`), and `rua=mailto:...` aggregate reporting URIs.
- **DKIM Selector Audit (`0–20 pts`)**: Probes common or custom `--dkim-selector` entries (with CNAME resolution), flagging revoked (`p=`) keys, testing mode (`t=y`), and weak `<2048-bit` RSA keys.
- **Exact Copy-Paste DNS Fix Records**: Automatically outputs zone-ready `TXT` and `MX` records (including deduplicated merged SPF records and upgraded DMARC records).
- **CI/CD & Automation Ready**: Supports `--domain`, `--file` (text/CSV or `-` stdin), `--format text|json|csv`, and `--min-score <N>` exit gate (`0` pass, `1` below threshold, `2` input/CLI error).

## Quick Start

### 1. Audit a single domain

```bash
python deliverability_cli.py --domain example.com
```

Example output:

```text
=== example.com | Score: 33/100 (Grade D) ===
[MX    20/20] PASS    | Hosts: 10 mail.example.com
[SPF    0/30] FAIL    | Lookups: 1/10 | Policy: +all
  Record : v=spf1 mx +all
  Lookups: mx
[DMARC 13/30] WARN    | Policy: none | pct: 100% | rua: none
  Record : v=DMARC1; p=none
[DKIM   0/20] MISSING | Selectors: none found (probed: google, selector1, selector2, default, dkim, k1, s1, s2, mail)
Findings:
  - [ERROR] (SPF/SPF_PLUS_ALL) SPF ends with '+all' (allow any host on the internet to spoof this domain!).
  - [WARN] (DMARC/DMARC_POLICY_NONE) DMARC policy is 'p=none' (monitoring only — spoofed emails are still delivered).
  - [WARN] (DMARC/DMARC_MISSING_RUA) DMARC record has no valid 'rua=mailto:...' aggregate reporting URI; delivery failures remain invisible.
  - [WARN] (DKIM/DKIM_NOT_FOUND) No active DKIM TXT records found across probed selectors (...). Pass --dkim-selector <name> if your provider uses a custom selector.
Copy-Paste DNS Fix Records:
  ; SPF: Replace insecure '+all' with '-all' (hardfail) or '~all' (softfail during rollout).
  example.com.  3600  IN  TXT  "v=spf1 mx -all"
  ; DMARC: Ensure single DMARC record with enforced policy (quarantine/reject) and aggregate rua reporting.
  _dmarc.example.com.  3600  IN  TXT  "v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@example.com; adkim=r; aspf=r; pct=100"
  ; DKIM: Publish a 2048-bit DKIM public key generated by your email provider / MTA.
  google._domainkey.example.com.  3600  IN  TXT  "v=DKIM1; k=rsa; p=<YOUR_2048_BIT_BASE64_PUBLIC_KEY>"
```

### 2. Batch-audit domains from a file with a CI score gate

```bash
# Audit domains from a list or CSV and fail CI (exit 1) if any domain scores < 80
python deliverability_cli.py --file domains.txt --min-score 80

# Custom DKIM selector & JSON export
python deliverability_cli.py --domain acme.io --dkim-selector acme2026 --format json

# Export multi-domain audit summary to CSV via custom DNS resolver
python deliverability_cli.py -d acme.io -d mail.acme.io --dns-server 8.8.8.8 --format csv > report.csv
```

## CLI Options & Exit Codes

| Flag | Default | Description |
| :--- | :--- | :--- |
| `-d`, `--domain` | `—` | Target domain name (repeatable; positional domains also accepted) |
| `-f`, `--file` | `—` | Path to plain-text or CSV file of domains (`-` for stdin) |
| `--format` | `text` | Output format: `text`, `json`, or `csv` |
| `--min-score` | `—` | CI gate threshold (`0–100`): exits `1` if any domain scores below `N` |
| `--dkim-selector` | common defaults | DKIM selector(s) to probe (repeatable or comma-separated) |
| `--dns-server` | `1.1.1.1`, `8.8.8.8` | Custom recursive DNS server IP (repeatable) |
| `--timeout` | `3.0` | Per-query DNS socket timeout in seconds |
| `--retries` | `1` | DNS query retries after initial attempt |
| `--no-fixes` | `false` | Hide copy-paste DNS fix records in `text` output |

**Exit Codes:** `0` = all domains passed (or `--min-score` not set), `1` = one or more domains scored below `--min-score`, `2` = invalid CLI arguments or unreadable input file.
